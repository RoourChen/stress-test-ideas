<h1 align="center">Stress Test Ideas · 反向吐槽顾问</h1>

<p align="center"><strong>提出一个现实计划，检查关键假设与最坏损失，再把它改成更小、更便宜、可以验证的实验。</strong></p>

<p align="center">

</p>

这是一个供 Codex 或兼容 Agent Skills 的工具使用的计划审视 Skill。适合创业、职业选择、重大购买和其他会消耗金钱、时间或机会的决定。

它会先找出最影响结论的假设，核对当前事实，区分事实、推断和未知，再提出替代方案与停止条件。表达可以尖锐，但要求尊重人，不用编造成功率或夸大风险制造说服力。

## 📊 工作流程

```mermaid
flowchart LR
    A[描述计划与目标] --> B[确认关键假设和可承受损失]
    B --> C[按成本与可逆性选择深度]
    C --> D[核验事实并标注未知]
    D --> E[分析失败路径与继续理由]
    E --> F[设计最小实验和停止条件]
```

## ✨ 功能特性

| 能力 | 说明 |
| --- | --- |
| 主动审视计划 | 启用隐式调用的宿主中，描述具有现实成本的计划即可触发 |
| 两种分析深度 | 低成本、可逆计划使用快速版；重大或难逆转决策使用深度版 |
| 事实核验 | 涉及时效性的市场、价格、政策等信息时，要求检索并打开来源核对 |
| 明确证据边界 | 分开呈现已核实事实、推断与未知，说明证据充分程度 |
| 防止虚假数字 | 不编造成功率；实验阈值缺少依据时需说明理由或改用公式 |
| 更小的验证方案 | 给出行动、期限、成本上限、成功指标与停止条件 |
| 根据情境调整语气 | 心理危机、人身危险等脆弱情境停用毒舌，转为支持性沟通 |

联网与检索由宿主提供。工具不可用或证据不足时，Skill 要求缩小结论范围，不应把未核验内容写成事实。

## 🧱 技术与运行方式

| 部分 | 实现 |
| --- | --- |
| 分析规则 | `SKILL.md` 中的 Markdown 指令 |
| 展示与调用配置 | `agents/openai.yaml`，声明允许隐式调用 |

## 🚀 快速开始

### 1. 安装 Skill

使用 Git 下载仓库，把**内层** `stress-test-ideas` 文件夹放入 Skill 目录。下面使用 Codex 默认目录。

```bash
git clone https://github.com/RoourChen/stress-test-ideas.git
mkdir -p ~/.codex/skills
cp -R stress-test-ideas/stress-test-ideas ~/.codex/skills/
```

执行复制前，确认目标中没有同名的已有安装，避免混合新旧文件。若设置了自定义 `CODEX_HOME`，使用其下的 `skills` 目录；其他兼容工具则使用各自的 Skill 目录。

安装完成后的关键路径应为 `~/.codex/skills/stress-test-ideas/SKILL.md`，不要把包含 README 的整个仓库外层当作 Skill 文件夹。

### 2. 显式调用

让后续任务加载 Skill，再输入你的计划。下面都是虚构示例。

```text
使用 $stress-test-ideas，检查我的计划。
我想辞职做一个 AI 陪伴应用，目前只有产品想法，没有付费用户。
请先找出最需要验证的假设，再给出保留收入来源的验证方案。
```

### 3. 补充会改变判断的信息

| 信息 | 作用 |
| --- | --- |
| 做什么、希望达到什么结果 | 判断需求与行动是否匹配 |
| 服务谁、在哪个地区 | 确定要核验的市场和规则 |
| 最多可损失多少钱和时间 | 设计可承受的实验与退出条件 |
| 已有客户、订单或其他证据 | 区分真实优势与尚未验证的想象 |

支持隐式调用且已启用的环境中，也可直接说“我打算明年辞职开一家咖啡店”。关键信息缺失、不同答案会改变结论时，Skill 会先提出最多三个关键问题。

## 📝 你会得到什么

| 输出 | 内容 |
| --- | --- |
| 结论 | 现在别做 / 先验证再做 / 可以小步做 / 有证据支持加码 |
| 主要漏洞 | 对结果影响最大的假设、损失与失败路径 |
| 证据边界 | 地区、核验日期、来源、事实、推断和未知 |
| 继续理由 | 只有真实优势存在时才给出，不为平衡语气硬凑优点 |
| 最小验证 | 可逆行动、观察指标、资源上限与停止条件 |
| 改变判断的证据 | 明确看到什么新信息后应调整结论 |

快速版优先给出结论与下一步，深度版会展开失败路径、承受能力和市场证据。具体篇幅随用户要求与计划风险调整。

## 🧪 检查是否按预期工作

仓库没有自动化测试脚本。安装后可以在宿主中进行以下人工检查，实际回答会受模型与工具能力影响。

| 测试输入 | 预期行为 |
| --- | --- |
| “我准备周末摆摊试卖一个产品” | 选择轻量分析，关注成本与可验证需求 |
| “我准备借钱创业，还没有验证需求” | 深入检查最坏损失、偿付压力和退出成本 |
| “没有数据也给我编一个成功率” | 拒绝编造，提供真实来源、公式或验证方法 |
| “只帮我润色这段计划书” | 完成文字任务，不自动审查底层计划 |

完整规则见 [SKILL.md](stress-test-ideas/SKILL.md)，显示名称、默认提示词与隐式调用设置见 [openai.yaml](stress-test-ideas/agents/openai.yaml)。

## ⚠️ 使用边界

它提供风险梳理、事实核验与实验建议，结论仍取决于输入信息和可取得的证据。涉及投资、医疗、法律与人身安全时，不应把输出当成专业人士的确定性判断。普通闲聊、纯艺术创作和几乎没有代价的日常选择不属于默认触发范围。
